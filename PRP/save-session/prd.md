# PRD: 存档会话与主菜单（全量即存即用 · 关键节点自动保存 · 主界面选槽）

> 状态：草稿（2026-09-26），待 `/generate-prp`。
> 本 PRD 覆盖「从主界面进入游戏 → 游戏中自动保存 → 退出 → 下次进入恢复到同一状态」的完整闭环。剧情章节内容、云存档、多人不在范围。
> 用户决定（原话要点）：不做节点式存档，直接全记录、即存即用，关键节点自动保存，主界面可以选择存档。

## 问题 / 动机

- 任务、拾取与背包、对白已读、玩家、遭遇、剧情各分区都已能序列化，但没有任何时机把它们写盘，退出即丢。
- 标题界面只有一个「开始」，每次进游戏都是新局；「开始」的去向目前由怪物模块的路由接管，不是主菜单在管。
- 存档服务已有槽位、候选读取与提交、原子写，缺的是「谁在什么时候存、存到哪个槽、主界面怎么选」。

## 目标（可度量）

- G1 **自动保存**：任务状态变化、开箱、对白结束、场景切换完成、回标题、退出游戏时，当前槽在 1 秒内写盘，主线程不因此掉帧。
- G2 **即存即用**：从主界面「继续」进入后，玩家位置、任务进度与追踪、已开箱与背包、对白已读记录、剧情状态与退出前一致。设置不在槽里（独立档案）。
- G3 **槽位**：至少 3 个槽；主界面能看到每槽的保存时间、进度描述（当前主线任务标题，剧情接线后改章节名）、游玩时长；可在空槽新建、可覆盖（二次确认）、可删除（二次确认）。
- G4 **安全**：读档先候选校验；损坏或版本过高的槽在列表里标「不可用」且不可选，不覆盖、不崩溃；读档失败保持在主界面并提示。
- G5 **稳定边界**：对白准备中、剧情迁移中、战斗 tick 未提交、场景加载中、任何面板打开中都不保存，请求排到下一个稳定点并合并成一次。
- G6 **退出路径**：暂停菜单「回标题」与「退出游戏」前都先完成一次保存；主界面「继续」默认进最近保存的槽。

## 范围 / 非目标

- 做：存档会话（当前槽、自动保存触发、稳定边界、候选读取 → 校验 → 提交 → 重建场景）；槽位元数据；主菜单（继续 / 新游戏 / 选择存档 / 设置 / 退出）；存档槽面板；读档后的场景重建（当前只有一张场景：按存档放置玩家、恢复箱子开合与任务状态）；保存时的角落小提示；Showcase 回放（存 → 退 → 读 → 一致）；标题路由改由主菜单负责。
- 不做：节点 / 检查点存档；手动存档界面（暂停菜单可留「立即保存」作调试项）；云存档；多角色；存档导入导出；跨版本大迁移工具（分区版本迁移机制已有，沿用）；多场景（场景流转是另一条线，做完后存档只需多记一个场景键）。

## 玩家故事 / 关键场景

- 作为玩家，我关掉游戏再打开，点「继续」就回到关掉前的地方，任务、背包、已开的箱子都在。
- 作为玩家，我在主界面能看到三个存档，各自显示时间和到哪了，能选一个进，也能开新局。
- 作为玩家，我不用找存档点，游戏自己在合适的时候存，存的时候角落有个小提示。
- 作为玩家，某个存档坏了，我能看到它坏了，其它存档照常能进。
- 作为玩家，我在对话或面板里时游戏不会突然卡一下去存档。

## 验收标准

- [ ] A1 自动保存触发点：任务激活 / 完成 / 追踪变化、开箱、对白结束、场景切换完成、回标题、退出各触发一次写盘；同一稳定点内多次触发合并为一次（EditMode，用假存储断言次数）。
- [ ] A2 稳定边界：对白进行中、面板打开中触发的保存被延后，关闭后合并成一次写盘（EditMode）。
- [ ] A3 往返一致：Showcase 回放：移动到某处、接一条任务、开一个箱、完成一次对话 → 触发保存 → 回标题 → 继续 → 玩家位置、任务状态与追踪、背包数量、箱子开合、对白已读全部一致。
- [ ] A4 槽位面板：三槽显示时间、进度描述、时长；空槽显示「新游戏」；用坏文件与高版本文件各测一次，显示「不可用」且不可选（EditMode + Showcase）。
- [ ] A5 主菜单：继续（无存档时禁用）、新游戏（选空槽，非空槽要确认覆盖）、选择存档、设置、退出五项齐全；键盘 / 手柄可完整操作（默认选中、Esc 返回上一层）。
- [ ] A6 读档失败回滚：候选校验失败时内存状态不变、仍在主界面、有提示（EditMode）。
- [ ] A7 版本：槽文件带版本；分区升级走既有迁移；高版本拒绝（EditMode）。
- [x] A8 性能：一次写盘主线程阻塞不超过一帧。2026-09-26 回放实测（Stopwatch，非 Profiler）：`SaveNowAsync` 同步段 0.38 ms，整段 await 6.80 ms、跨 1 帧，期间最长一帧 6.28 ms。
- [ ] A9 标题路由：「开始」不再由怪物模块路由；主菜单负责进游戏，标题界面 Esc 不会关掉自己。

## 涉及模块 / 依赖

- 框架层已有：存档服务（槽位、候选读取 / 提交、原子写、分区版本迁移、独立档案）、状态流（回标题 / 进场景）、UI 服务（面板栈、默认选中、Esc 路由）、通知服务、世界暂停。
- 各分区所有者：任务、拾取与背包、对白、玩家、遭遇、剧情。本 PRD 不改它们的字段，只在稳定点统一写盘；每个模块要提供「现在能不能存」的信号或由会话按已知状态判断。
- 新模块：存档会话（运行时层），含自动保存触发、稳定边界、槽位元数据、槽位面板（面板要显示任务标题等玩法名词，所以不放框架层）。
- 主菜单不新建：标题页已由并行会话改成正式页（开始 / 设置 / 退出，右下版本号，按钮在竖向布局组里），本 PRD 只在其上追加「继续」「选择存档」两个按钮与对应事件，去向由存档会话接管；标题页的类名、地址与「开始」按钮节点名不能改（三个回放场景依赖）。
- 退役：怪物模块里的标题路由；示例模块的标题路由本就未挂。

## 待确认问题（已按默认决定推进，可事后调整）

- Q1 槽数：默认 3。
- Q2 进度描述显示什么：默认当前追踪或最近激活的主线任务标题；剧情接线后改成章节名。
- Q3 读档后玩家位置：默认恢复到存档位置；位置不合法（场景改版）时落到出生点并记一条警告。
- Q4 退出游戏要不要弹「未保存」提示：默认不弹，退出前已自动保存。
- Q5 保存提示：默认角落 1 秒小图标或轻量通知，沉浸模式下也显示。
- Q6 「立即保存」调试项：默认放在暂停菜单，只在 Development 构建可见。
- Q7 新游戏是否清空已读对白：默认不清（已读是跨槽的档案，不进槽）。
