# 任务（Quest）

> 状态：可用　·　是否已接进游戏：已挂 Boot　·　程序文档：[三件套](../../ai-docs/docs/modules/quest/quest-module-guide.md)

## 1. 一句话

告诉玩家「现在该做什么、去哪」：主线一条接一条推进，支线可以同时挂好几条，画面上常驻任务栏并有方向与距离指引。策划只改配置表就能串出一条主线和若干支线，不用写代码；对话、到达地点、其他玩法的计数都能推进任务。

## 2. 玩家看到什么、做什么

- 进入玩法场景后，画面左侧常驻一条任务栏：上面是当前追踪任务的标题，下面是当前目标（需要多次的目标显示「打开物资箱 1/3」这样的进度）。没有追踪任务时显示「未追踪任务」。
- 当前目标有地点时有指引：目标在画面内，目标头顶浮一个任务标记（此时不显示距离）；目标在画面外，画面边缘出现指向它的箭头和距离（整数米，如「11m」）。
- 走到目标地点、和指定 NPC 聊完，目标自动完成，任务栏切到下一个目标；任务全部目标完成后，后续任务自动接取。
- 接取和完成任务时画面上弹一条通知（「接取任务：xxx」「任务完成：xxx」）；刚进游戏时自动接取的任务不弹。
- 点任务栏打开任务面板，**打开期间世界暂停**，玩家不能移动。面板左边是已接取的任务列表（当前主线永远在第一行，其余按接取先后排），每项标「主线 / 支线」；点一项右边显示标题、类型、描述和全部目标（已完成打「✓」，未完成「○」）。
- 详情下方一个按钮：未追踪时是「追踪」，已追踪时是「取消追踪」。追踪切换后任务栏和指引立刻跟着换。
- 关闭面板后世界恢复。
- 对话进行中任务栏、头顶任务标记和边缘箭头都隐藏，对话结束恢复。

## 3. 规则

- 任务三种状态：未接取 → 进行中 → 已完成。已完成的任务不会回退，也不会在面板里显示。
- 接取条件：前置任务**全部**完成就自动接取；没有前置的任务在第一次进游戏时就接取。没有「找 NPC 接任务」这一步。
- 主线同一时刻最多一条进行中。多条主线同时满足前置时，编号最小的先接，其余等它完成后再按同样规则接。支线不限条数。
- 目标严格按顺序做：只有「当前目标」接收进度，后面的目标不会提前累计。当前目标攒够次数就完成并换下一个；最后一个完成则任务完成。
- 多出来的次数不结转：计数目标一次报了 5 但只要 3，完成后下一个目标从 0 开始。
- 同一个事实会同时推进所有「当前目标匹配它」的进行中任务（例如两条任务当前目标都是和老者对话）。
- 三种目标：
  - 与某人对话：填的那段对话以任何方式结束都算完成（选了拒绝、中途跳过都算），不看选了哪个结局。对话必须在目标成为当前目标**之后**进行，之前聊过的不算。
  - 到达地点：玩家进入场景里对应地点的判定半径即完成；目标成为当前目标时玩家已在范围内，会立刻完成。
  - 计数 / 标记：由其他玩法上报某个键，累计到需要次数完成。**目前游戏里没有任何玩法会上报计数**（见第 6 节）。
- 追踪：第一次进游戏默认追踪当前主线；同一时刻最多追踪一条；玩家可改追任一进行中的任务或取消追踪。被追踪的任务完成后自动切回当前主线（没有主线就不追踪）。取消追踪后不会自动再追。
- 指引：只对被追踪任务的当前目标显示。指引点的查找顺序是：目标填了指引地点就用它；否则到达地点用自己的地点键；否则与某人对话指向挂着那段对话的 NPC；计数目标不填指引地点就没有指引。找不到目标（地点不在当前场景）时不显示指引。距离是玩家到目标的直线距离，四舍五入到整米，不是寻路距离。
- 任务表有任何一处写错（编号重复、前置成环、对话编号在对话表里不存在等），整个任务系统启动失败：没有任务栏、没有任务。
- 必须从 Boot 场景进入、在标题点「开始」才有任务系统。

## 4. 策划能改什么

从零配一条任务的手把手流程见 [策划手册第 12 章](../designer-guide.md#12-配一条任务)，改表与生成的通用步骤（保存、生成、看 Console、进游戏验证）见 [第 4 章](../designer-guide.md#4-改配置表的完整流程)。

| 想改什么 | 在哪改 | 字段 / 表 | 改了影响什么 | 备注 |
| --- | --- | --- | --- | --- |
| 新增 / 修改一条任务 | [`Tables/Data/quest/`](../../Tables/Data/quest/) 下 `<编号>.json` | 任务表 TbQuest | 任务标题、描述、类型、前置、目标 | 改完必须跑「生成」 |
| 串主线顺序 | 同上 | `prerequisites` | 哪条完成后接哪条 | 主线只会同时开一条 |
| 场景里的任务地点 | 场景中挂 `Quest Location` 组件的物体 | Location Key / Radius | 到达判定与指引落点；现有 `camp`、`lookout`，半径都是 2 米 | 地点键要和表里一致，已加载的场景里不能重复；改完保存场景 |
| 与某人对话指向哪个 NPC | 场景 NPC 的 `Dialogue Interactable` 组件 | Dialogue Id | 任务按对话编号找 NPC | 见 [对话](dialogue.md) |
| 指引、标记、文案 | `Assets/_Project/Data/Quest/QuestConfig.asset` | 见下方全局参数表 | 所有任务的指引表现和固定文字 | 直接生效，不用生成 |

**任务表 TbQuest**：文件 `Tables/Data/quest/<编号>.json`，一个文件一条任务，文件名就是编号。**每个字段都必须写出来**，空的写 `""` 或 `[]`。

| 字段名 | 含义 | 取值 / 例子 |
| --- | --- | --- |
| `id` | 任务编号，全表唯一 | 整数，与文件名一致；现有主线用 1xxx、支线用 2xxx（惯例，不强制） |
| `kind` | 任务类型 | `Main` 主线 / `Side` 支线 |
| `title` | 标题，任务栏、面板、通知都显示它 | `"找到落脚处"` |
| `description` | 描述，只在面板详情里显示 | 一两句背景 |
| `prerequisites` | 前置任务编号列表，全部完成才接取 | `[1001]`；`[]` = 开局接取；不能成环 |
| `objectives` | 目标列表，按顺序逐个完成 | 至少一个，见下表 |

每个目标：

| 字段名 | 含义 | 取值 / 例子 |
| --- | --- | --- |
| `text` | 任务栏和面板里显示的目标文字 | `"与长者谈谈"` |
| `kind` | 完成条件类型 | `TalkTo` 与某人对话 / `ReachLocation` 到达地点 / `Counter` 计数 / 标记 |
| `key` | 条件参数，含义随 `kind` 变 | `TalkTo` 填对话树编号（必须是整数且对话表里存在，如 `"1001"`）；`ReachLocation` 填地点键（不能空，如 `"camp"`）；`Counter` 填和程序约定的键（如 `"crate"`） |
| `count` | 需要次数 | 从 1 起；大于 1 时任务栏显示「n/次数」 |
| `location` | 指引地点键（场景里的 Location Key） | `""` = 到达地点用自己的 `key`、与某人对话指向该 NPC、计数目标无指引；填了就改为指向这个地点 |

新增一种完成条件类型（比如「拾取某道具」）要改代码，找程序。

**全局参数 `QuestConfig.asset`**（Inspector 悬停字段名有中文说明，改法见 [策划手册第 3 章](../designer-guide.md#3-改数值两条路怎么选)）：

| 想改什么 | 在哪改 | 字段 / 表 | 改了影响什么 | 备注 |
| --- | --- | --- | --- | --- |
| 边缘箭头离屏幕边多远 | `QuestConfig.asset` | Edge Margin | 当前 48 像素（按 1920×1080 参考分辨率） | |
| 画面内指引上移多少 | 同上 | Hover Offset | 当前 80 像素；**目前不起作用** | 画面内已改为头顶任务标记，不再画屏幕指引，此项是遗留参数 |
| 距离数字刷新频率 | 同上 | Distance Refresh Interval | 当前 0.2 秒一次 | 最小 0.02 |
| NPC 头顶标记高度 | 同上 | Marker Lift | 当前在 NPC 碰撞体顶部再抬高 0.3 米 | |
| 地点标记高度 | 同上 | Location Marker Height | 当前离地 1.5 米（没有碰撞体的 NPC 也用它） | |
| 标记用哪个预制体 | 同上 | Target Marker Address | 当前 `QuestTargetMarker` | 美术资源地址，一般别动 |
| 未追踪时的文字 | 同上 | Untracked Label | 当前「未追踪任务」 | |
| 主线 / 支线标签 | 同上 | Main Kind Label / Side Kind Label | 当前「主线」「支线」 | |
| 接取通知文字 | 同上 | Activated Notification Format | 当前「接取任务：{0}」，`{0}` 换成任务标题 | 留空只显示标题 |
| 完成通知文字 | 同上 | Completed Notification Format | 当前「任务完成：{0}」 | 同上 |

两条通知格式在资产文件里还没写入，当前按上面列的默认值生效；在 Inspector 里改一次并保存就会写进资产。通知停留时长由通用界面配置 `Assets/_Project/Data/UI/UIConfig.asset` 的 Notification Seconds 决定（默认 2.5 秒），影响所有通知。

## 6. 已知限制与还没做的

- 任务进度不落盘：游戏里还没有任何存档时机，关掉重进任务从头开始（roadmap E1）；也没有「新游戏重置进度」和已完成任务列表（roadmap B4）。
- 没有奖励：完成任务不给任何东西，道具表也还没有消费方（roadmap B1，需要策划先定奖励是信息还是物品）。
- 接取 / 完成通知已在工作区做好（第 2 节所述），但尚未提交；roadmap B2 状态还写着「待做」，以实际合入为准。
- 完成任务不会写剧情标记，所以对话选项读不到任务结果（roadmap B3，依赖 C2）。
- 计数目标没有上报来源：物资箱等可交互物还不存在（roadmap A3），2002 无法完成。
- 任务只能靠前置自动接取，不能通过对话选项接取；对话结局也不影响任务（roadmap C1）。
- 不做：任务失败、限时、放弃、多语言、小地图（roadmap 第 4 节「任务系统的边界」）。
- 指引只在当前场景内有效，只有一张可玩场景，跨场景任务点要等多场景流转（roadmap A4）。
- 任务面板只能点任务栏打开，没有键盘 / 手柄快捷键。
- 任务面板底板在实机偶尔透底，原因未定位（roadmap 2.5 第 7 条）。

## 7. 和其他模块的关系

- 依赖 [对话](dialogue.md)：对话结束推进「与某人对话」目标；按对话编号找 NPC 做指引；复用对话模块给玩家根物体挂的标记做测距起点，没有对话模块的场景就没有到达判定和指引。
- 将被 [叙事阶段](narrative.md) 使用：任务完成写剧情标记、剧情推进接取任务，均未接（roadmap B3、C1）。
- 将被物资箱 / 背包等新模块使用：由它们上报计数目标、领取任务奖励（roadmap A3、B1）。
- 与 [探索表现](isometricexploration.md) 配合：头顶任务标记朝向相机；沉浸模式下标记与箭头一并隐藏。
