# 策划手册

写给不写代码、但要自己改数值、加道具、调平衡的人。目标是：**今天拿到工程，今天就能自己改一次表、在编辑器里看到效果。**

> 本文对应工程状态：**2026-09-15，框架脚手架五波完成**。工程里目前只有一个示例玩法模块 `Sample`，正式玩法未定。
> 讲代码怎么写的是 [`developer-guide.md`](developer-guide.md)（开发手册），讲为什么这么设计的是 [`architecture.md`](architecture.md)。本文不重复它们，需要细节时会指过去。

## 1. 这份文档管什么

一句话：**数值你自己改，结构改动找程序。**

| 你自己就能做完 | 必须先找程序 |
| --- | --- |
| 改已有表里的数值（价格、名字、品质…） | 加一整张新表（技能表、关卡表） |
| 在已有表里加一行、删一行 | 给已有表加一个新字段（新列） |
| 加一个新的枚举值（新品质、新类型） | 给已有列改名字 |
| 改 Inspector 上已有的旋钮（UI 过渡时长、音效声部数…） | 加一个新的旋钮（新的配置项） |
| 跑一次「生成」，进 Play 看效果 | 任何「游戏行为」变化（新逻辑、新界面） |

## 2. 第一次准备

### 2.1 要装什么

| 装什么 | 版本 | 干什么用 | 怎么装 |
| --- | --- | --- | --- |
| Unity Hub | 最新稳定版 | 管理编辑器版本 | 官网下载，或命令 `winget install Unity.UnityHub` |
| Unity 编辑器 | **2022.3.62f2**（精确到这个小版本） | 打开工程、看效果 | Hub → Installs → Install Editor → Archive 里找；或浏览器打开深链 `unityhub://2022.3.62f2/7670c08855a9` |
| Excel 或 WPS 表格 | 任意 | 改 `.xlsx` 配置表 | 已有就行 |
| .NET SDK | 8.0 或更高 | **生成配置表要它**，不装就跑不了生成 | `winget install Microsoft.DotNet.SDK.8` |
| Git 客户端 | 任意 | 拿到工程、把改动交给程序 | 不会用命令行就装个图形客户端，或让程序帮你拉一份 |

几点容易搞混的：

- **Luban 不用你装**。它是把 Excel 变成游戏能读的数据的那个工具，第一次点「生成」时脚本会自动从 GitHub 下载约 30 MB 放进 `Tools/Luban/`，所以第一次生成要能上 github.com（公司网连不上就找程序，见开发手册 8.4）。
- **.NET 必须你自己装**。生成脚本只会自动下 Luban，不会装 .NET；找不到 .NET 时它直接失败，红字写着「PATH 里没有 dotnet」。装完要**重开一个终端 / 重开 Unity**，新装的东西才会被认出来。
- 解压用的是 Windows 自带的工具，一般不用管；万一报「解压失败」，装个 7-Zip 就好（`winget install 7zip.7zip`）。

### 2.2 拿到工程

工程用 Git 管。最省事的做法是**让程序帮你在本机拉一份**，你只要记住工程根目录在哪（本文里所有路径都是从这个根目录数起的，比如 `Tables/Data/item.xlsx`）。

如果你也装了 Claude Code，在工程根目录开一个会话跑 `/onboard`，它会逐项检查环境、缺什么告诉你什么。没装就照 2.1 装完、让程序陪你走一遍第 2.3 节。

### 2.3 确认能跑起来（第一天必做）

1. Unity Hub → Add → 选工程根目录 → 用 2022.3.62f2 打开。
2. 第一次打开要等几分钟（右下角进度条转完为止），中途别点来点去。
3. 在 Project 窗口里找到 `Assets/_Project/Scenes/Boot.unity`，双击打开。
4. 点上方正中的 **Play**（▶）按钮 → 看到标题界面 → 点「开始」→ 进入示例场景 → 点「返回标题」能回来。
5. 看 Console 窗口，应该有一行 `[Game] 进入 SampleState：精钢长剑 ×3　原价 300／个，减 20% 后 240／个，共 720`。

**这一行就是配置表读成功的证据**，第 4 章验证改动也看它。

> 一个已知现状，不是你弄坏了：
> Console 里一条日志都没有时，先点亮 Console 窗口右上角那三个等级按钮（Log / Warning / Error），它们是过滤器，关着就什么都不显示（开发手册 15.7）。

## 3. 改数值：两条路怎么选

工程里数值只有两个去处，选错了会很别扭：

| 你要调的东西长什么样 | 走哪条 | 放在哪 | 例子 |
| --- | --- | --- | --- |
| 成体系、按 id 查、条目会越来越多、要批量调 | **配置表** | `Tables/Data/*.xlsx` | 道具、关卡、怪物、技能 |
| 全局只有一份的旋钮、一个模块就一套 | **ScriptableObject 资产** | `Assets/_Project/Data/<模块>/*.asset` | UI 过渡时长、音效声部数、示例订单 |

代价对比（这决定了你一天能改几轮）：

| | 配置表 | ScriptableObject 资产 |
| --- | --- | --- |
| 改完要做什么 | **必须跑一次「生成」**（第 4 章），忘了就不生效 | 直接生效，下次 Play 就是新值 |
| 适合多少条 | 几十到几万条都行 | 三五个旋钮；上百条就该进表了 |
| 用什么改 | Excel / WPS | Unity 的 Inspector 面板 |
| 交给程序时 | `.xlsx` 是二进制文件，两个人同时改同一张表**合不了**，动手前先吱一声 | `.asset` 是文本，冲突好解 |

### 现在工程里有哪几份 ScriptableObject 资产

| 资产 | 里面是什么 | 现值 |
| --- | --- | --- |
| `Assets/_Project/Data/UI/UIConfig.asset` | 参考分辨率、宽高匹配系数、面板淡入淡出秒数 | 1920×1080、0.5、0.15 秒 |
| `Assets/_Project/Data/Audio/AudioConfig.asset` | 混音器（留空）、同时能响几个音效、BGM 默认淡入淡出秒数 | 空、8、0.5 秒 |
| `Assets/_Project/Data/Dialogue/DialogueConfig.asset` | 对话表现：打字速度、历史上限、倍速档、三连点补全、自动播放间隔（见第 11 章） | 35 字/秒、500、x1/x2/x4、3 次 0.5 秒内、1.5 秒 |
| `Assets/_Project/Data/Sample/SampleConfig.asset` | 示例模块展示的那笔订单：道具 id、买几个、打几折 | 1002、3、0.2 |

怎么改：在 Project 窗口点开那个 `.asset` → 右边 **Inspector** 里改 → `Ctrl+S` 保存工程 → 点 Play 看效果。

Inspector 上显示的是**英文字段名**（`Transition Seconds`、`Sfx Voices`、`Item Id` 这种），**鼠标悬停在字段名上会弹出中文说明**，取值范围也写在那儿，照着填就行。

> **别在 Play 模式里改这些资产**：场景里物体的改动退出 Play 会还原，但 ScriptableObject 的改动会**真的写进文件**，很容易改了自己都不知道。先退出 Play 再改。

## 4. 改配置表的完整流程

目前工程里只有一张数据表：`Tables/Data/item.xlsx`（道具表）。下面以它为例。

### 4.1 表长什么样

打开 `Tables/Data/item.xlsx`，你会看到：

| | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- |
| 第 1 行 | `##` | `id` | `name` | `quality` | `price` | `tags` |
| 第 2 行 | `##` | 道具 id（主键） | 道具名 | 品质（Common/Rare/Epic） | 售价（金币） | 标签，英文逗号分隔 |
| 第 3 行 | | 1001 | 铁剑 | Common | 50 | 武器,近战 |
| 第 4 行 | | 1002 | 精钢长剑 | Rare | 300 | 武器,近战,锻造 |
| 第 5 行 | | 1003 | 龙鳞护甲 | Epic | 1200 | 防具,重甲 |
| 第 6 行 | | 1004 | 治疗药水 | Common | 20 | 消耗品,回复 |

要记住的只有四条：

- **A 列的 `##` 是「这一行不是数据」的标记**，第 1、2 行各有一个，**一个都不能删**。数据行的 A 列留空。
- **第 1 行是字段名**（`id`、`name`…），它们就是程序代码里的名字，**你不能改**。想让表更好认，改第 2 行。
- **第 2 行是中文说明**，随便你改，只影响你自己看。
- **数据从第 3 行开始**，一行一条。

逐列怎么填：

| 列 | 填什么 | 规矩 |
| --- | --- | --- |
| `id` | 整数，这条数据的编号 | **主键，全表不能重复**；程序按它查数据，定了就别乱改 |
| `name` | 文字 | 随便填 |
| `quality` | 品质 | 只能填 `Common` / `Rare` / `Epic` 这三个**英文名**之一，来源见第 6 章 |
| `price` | 整数 | 留空会被当成 0，且**不报错**——别靠留空表示「没有」 |
| `tags` | 标签列表 | 一个单元格里写多个，**用英文逗号分隔**（`武器,近战`），别用中文逗号 |

### 4.2 六步流程

1. **打开表**：`Tables/Data/item.xlsx`。在 Unity 里点菜单 **`21Days` → `配置表` → `打开 Tables 目录`** 可以直接定位到这个文件夹。
2. **改**：从第 3 行往下，按 4.1 的规矩填。
3. **保存并关掉 Excel**：`Ctrl+S` 之后关掉。
   - **没保存是头号坑**：磁盘上还是老文件，生成出来仍然是旧数值，而且**一声不吭地成功**，你会以为改了却没生效。
   - 文件被独占占用时生成会直接失败，红字里带 `加载表文件失败` 和 `because it is being used by another process`。
4. **回 Unity 点菜单 `21Days` → `配置表` → `生成`**。会弹一个进度条写着「正在跑 gen-tables.ps1（首次会下载 Luban，约 30 MB）…」，第一次慢一点，之后一般几秒。
   （不想点菜单也可以在工程根目录跑这一行：`powershell -ExecutionPolicy Bypass -File scripts/gen-tables.ps1`）
5. **看 Console**：成功长这样——
   - `[配置表] 完成：7 个 .cs，1 个 .bytes（tbitem.bytes）`
   - `[配置表] 生成完成，资产已刷新。别忘了生成物（Generated/ 与 Data/Config/）要一起提交。`
   失败会是红字 `[配置表] 生成失败，退出码 N`，往上翻能看到 Luban 的原始报错——照第 8 章对号入座。
6. **进 Play 验证**：打开 `Assets/_Project/Scenes/Boot.unity` → Play → 点「开始」→ 看 Console 里 `[Game] 进入 SampleState：…` 那行数字对不对。

### 4.3 例子：加一件新道具「回城卷轴」

1. 打开 `Tables/Data/item.xlsx`，在第 7 行（第一条空行）填：

   | A | B（id） | C（name） | D（quality） | E（price） | F（tags） |
   | --- | --- | --- | --- | --- | --- |
   | 留空 | `1005` | `回城卷轴` | `Rare` | `80` | `消耗品,传送` |

2. `Ctrl+S`，关掉 Excel。
3. Unity → `21Days` → `配置表` → `生成`，Console 看到「生成完成，资产已刷新」。
4. 想立刻在游戏里看到它：点开 `Assets/_Project/Data/Sample/SampleConfig.asset`，把 Inspector 上「展示用的一笔订单」里的 **Item Id**（悬停提示写着「道具 id，要能在配置表 TbItem 里查到」）从 `1002` 改成 `1005`，`Ctrl+S`。
5. Play → 点「开始」→ Console 里应该出现
   `[Game] 进入 SampleState：回城卷轴 ×3　原价 80／个，减 20% 后 64／个，共 192`。

看到这行，你就完整走通了一轮「改表 → 生成 → 看到效果」。

## 5. 加一张新表（要先找程序）

**先说结论**：新表跑完生成后会自动被游戏读进内存，**框架代码一行不用改**；但要让这张表的数值**真的影响游戏**，得有程序写代码去读它。所以加表之前先和程序对一遍：表叫什么、有哪些字段、谁来用。

要动三个地方（以已有的道具表为例）：

**① `Tables/Data/__tables__.xlsx`——表清单，一张表一行。** 现有的 `TbItem` 这行是这么填的：

| 列 | 值 | 什么意思 |
| --- | --- | --- |
| `full_name` | `TbItem` | 表名，程序按这个名字找表；习惯是 `Tb` + 结构名 |
| `value_type` | `Item` | 这张表每一行是什么结构，对应 ② 里定义的名字 |
| `read_schema_from_file` | `FALSE` | 用 ② 里定义好的结构（填 `TRUE` 是从数据表头猜，本工程不用） |
| `input` | `item.xlsx` | 数据文件名，**相对 `Tables/Data/`，不要写 `Data/` 前缀** |
| `index` | `id` | 主键字段名 |
| `mode` | 留空 | 留空即可 |
| `group` | `c` | 客户端用，照抄 |
| `comment` | `道具表` | 中文说明 |

（右边还有 `tags`、`output` 两列，留空即可。）

**② `Tables/Data/__beans__.xlsx`——结构定义，说明「一行数据由哪些字段组成」。** 左半边一行定义结构本身（`full_name` = `Item`、`comment` = `道具`），右半边 `*fields` 区**逐行**写字段：`name`（字段名，英文）、`type`（类型）、`comment`（中文说明）。道具表的五个字段就是 `id`/`int`、`name`/`string`、`quality`/`EItemQuality`、`price`/`int`、`tags`/`(list#sep=,),string`。

常用类型：`int`（整数）、`long`（大整数）、`float`（小数）、`bool`（真假）、`string`（文字）、枚举名（见第 6 章）、`(list#sep=,),string`（一个单元格里塞多个值，逗号分隔）。**拿不准就问程序**，类型写错的报错很难看懂。

**③ 建数据文件 `Tables/Data/<表名>.xlsx`**：A1 写 `##`，B 列起写字段名；第 2 行 A 列也写 `##`，其余填中文说明；第 3 行起是数据，A 列留空。照 `item.xlsx` 抄最快。

> ⚠️ `__beans__.xlsx` 和 `__enums__.xlsx` 的表头里，`*fields` / `*items` 那一格是**合并单元格**（横跨它下面所有子列）。**不要拆开、不要重排表头**，拆了会报「缺失列」这种看不懂的错（开发手册 15.3 记了这个坑）。加字段就在下面**加行**，别动表头。

## 6. 枚举怎么加

枚举就是「这一列只能从几个固定值里选」，比如道具品质。定义在 `Tables/Data/__enums__.xlsx`：左半边一行定义枚举本身（`full_name` = `EItemQuality`、`comment` = `道具品质`），右半边 `*items` 区**逐行**写每个值：

| `name` | `alias` | `value` | `comment` |
| --- | --- | --- | --- |
| `Common` | 普通 | 1 | 白色品质 |
| `Rare` | 稀有 | 2 | 蓝色品质 |
| `Epic` | 史诗 | 3 | 紫色品质 |

加一个「传说」品质，就在下面加一行：`name` = `Legendary`、`alias` = `传说`、`value` = `4`、`comment` = `橙色品质`。加完**跑一次生成**，之后 `item.xlsx` 的 `quality` 列才能填 `Legendary`。

**为什么 `name` 必须是英文**：这一列会**原样变成程序代码里的名字**（程序写的是 `EItemQuality.Rare`），中文塞进去程序那边没法正常用。中文写在 `alias` 和 `comment` 列，它们就是给人看的。

还有一条连带规矩：**数据表里填的就是 `name`，一个字都不能差**。把 `Rare` 改成别的名字而没同步改 `item.xlsx`，生成会报 `'Rare' 不是 enum:'EItemQuality' 的有效枚举值`。

## 7. 绝对不要做的事

| 不要做 | 为什么 |
| --- | --- |
| 改 `Assets/_Project/Data/Config/` 里的 `.bytes` | 这是 Excel 生成出来的结果文件，下次生成直接覆盖，白改；AI 助手的护栏也会当场拒绝写入 |
| 改 `Assets/_Project/Scripts/Core/Config/Generated/` 里的代码 | 同上，也是生成物，改了下次生成就没了 |
| 删掉 Excel 里 A 列的 `##` 标记行 | 删了第 1 行的 `##`，生成报「不包含有效的工作表(有效工作表的 A1 单元格必须是 ##)」；删了第 2 行的 `##`，那行中文说明会被当成数据，报「道具 id（主键） 不是 int 类型值」 |
| 改第 1 行的列名（字段名） | 列名等于程序那边的字段名，改了生成就报 `bean:'Item' 缺失列:'price'`，程序那边也编译不过 |
| 把表另存成 `.csv` / `.xls`，或改文件名 | `__tables__.xlsx` 的 `input` 列写死了文件名，找不到就报「input 文件或目录不存在」 |
| 自己 `git commit` / `git push` | 工程硬规则：改动攒在工作区，由程序列清单、确认后统一提交（见第 9 章和 [`../CLAUDE.md`](../CLAUDE.md)） |
| 在 Play 模式里改 ScriptableObject 当试数值 | 那些改动会真的写进文件，退出 Play 也不会还原 |

## 8. 改出问题了怎么办

**先看 Console 的第一条红字**，红字里带路径和行列号，八成能自己对上号。

### 生成失败（Console 里 `[配置表] 生成失败，退出码 N`）

| 红字里出现 | 说明 | 怎么办 |
| --- | --- | --- |
| `PATH 里没有 dotnet` | .NET 没装 | 按 2.1 装 .NET SDK 8，装完重开 Unity |
| `加载表文件失败` + `because it is being used by another process` | 表还被占着 | 关掉 Excel 重跑 |
| `主键字段:'id' 主键值:'1001' 重复` | 两行填了同一个 id | 找出重复的 id 改掉 |
| `'传说' 不是 enum:'EItemQuality' 的有效枚举值` | 枚举列填了不存在的值（常见于填了中文） | 改成 `__enums__.xlsx` 里的**英文 `name`**，或先去加这个枚举值（第 6 章） |
| `bean:'Item' 缺失列:'price'` | 数据表里少了这一列，或列名被手滑改了 | 把第 1 行的列名改回来（对照 `__beans__.xlsx` 的字段名） |
| `不包含有效的工作表(有效工作表的 A1 单元格必须是 ##)` | A1 的 `##` 没了 | 在 A1 补回 `##` |
| `道具 id（主键） 不是 int 类型值` | 第 2 行 A 列的 `##` 没了，中文说明被当成了数据 | 在第 2 行 A 列补回 `##` |
| `'TbItem' 的 input 文件或目录不存在` | `__tables__.xlsx` 的 `input` 写错了 | 只写文件名（`item.xlsx`），**别带 `Data/` 前缀** |
| `缺失列:'alias'` 之类的「子结构缺列」 | `__beans__` / `__enums__` 表头的合并单元格被拆了 | 见第 5 章末尾的警告，或找程序（开发手册 15.3） |
| 下载 Luban 失败 / 网络报错 | 连不上 github.com | 换网络，或让程序按开发手册 8.4 手动放一份到 `Tools/Luban/` |

### 生成成功了，但游戏里还是老数值

按这个顺序查：

1. **Excel 保存了吗**？没保存就生成，等于没改（最常见）。
2. **点生成了吗**？只改 Excel 不点菜单，游戏永远读不到。
3. **改的是不是那张表**？确认路径是 `Tables/Data/`，不是桌面上另存的那份。
4. **Play 之前退出过 Play 吗**？改了资产要退出 Play 再重新进。
5. **看的是不是同一条数据**？示例界面只展示 `SampleConfig.asset` 里那个 id 的道具，改的是别的 id 当然看不出来。

### Play 之后一堆红字 / 界面不出来

| 红字里出现 | 大概是什么 |
| --- | --- |
| `标签 "config" 下一个资源都没有` | 工程配置被动过了，**找程序**（开发手册 15.5） |
| `配置表 "xxx" 的数据文件没找到` | 生成的数据没跟上，重跑一次生成；还不行找程序 |
| 其它看不懂的 | 截 Console 第一条红字给程序，别自己乱试 |

## 9. 和程序怎么配合

### 谁做什么

| 事情 | 谁做 |
| --- | --- |
| 改已有表的数值、加行删行 | 你，改完跑生成 |
| 加枚举值 | 你，改完跑生成 |
| 改 Inspector 上已有的旋钮 | 你 |
| 加新表、加新字段、改列名 | 你填 Excel，**程序跟一段代码**，先对齐再动手 |
| 加一个新的旋钮（现在没有的配置项） | 程序加字段，之后你在 Inspector 上调 |
| 任何玩法行为变化 | 程序 |

### 改完怎么交

**不要自己 `git commit` / `git push`。** 这是工程硬规则（[`../CLAUDE.md`](../CLAUDE.md) 第 4 条）：改动先攒在工作区，由程序统一列清单、经确认后一次性提交。你要做的只有三件事：

1. Excel 保存了、Excel 关掉了；
2. 跑过一次「生成」，Console 里是「生成完成」；
3. 告诉程序**你改了什么**——比如「我在 `Tables/Data/item.xlsx` 加了 1005 回城卷轴，已经跑过生成，Play 里数值对」。

生成会连带产出 `Assets/_Project/Scripts/Core/Config/Generated/` 和 `Assets/_Project/Data/Config/` 两处文件，它们要和 Excel 一起提交，**程序会处理，你不用管**。

### 两条省事的习惯

- **动表之前吱一声**：`.xlsx` 是二进制文件，两个人同时改同一张表，Git 合不了，只能有一个人的改动作数。
- **一次只改一件事**：改完验证完再改下一件。攒了一大堆再一起验证，出错就不知道是哪条引起的。

## 10. 名词对照

你会在界面和报错里看到这些英文词，只解释你真会碰到的：

| 词 | 一句话解释 |
| --- | --- |
| **Inspector** | Unity 右边那块面板，选中一个东西就在这儿显示它的所有可调参数 |
| **Project 窗口** | Unity 左下那块，工程里所有文件的目录树，找 `.asset` 就在这儿找 |
| **Console** | Unity 的日志窗口，报错、警告、我们自己打的日志都在这儿；右上角三个按钮是等级过滤器，都点亮才看得全 |
| **Play 模式** | 点上方 ▶ 按钮在编辑器里试玩；**退出前改的场景内容会还原，改的 `.asset` 不会** |
| **ScriptableObject** | 一种「只装数据、不挂在场景里」的配置资产，就是 `Assets/_Project/Data/` 下那些 `.asset`，点开在 Inspector 里改 |
| **Addressables** | Unity 管资源加载的机制，游戏靠它找到场景、界面和配置数据。它的窗口里的东西**别动**，动坏了游戏会找不到资源 |
| **asmdef** | 代码的分组文件，跟你没关系，看到了绕开 |
| **Luban** | 把 Excel 变成游戏能读的数据的工具，就是「生成」那一步在跑的东西 |
| **`.bytes`** | 生成出来的数据文件（`Assets/_Project/Data/Config/tbitem.bytes`），游戏真正读的是它，**不要手改** |

## 11. 配一段对话

对话内容不在 Excel 里，而是 **JSON 文本文件**，同样经 Luban 生成。程序侧的完整约定见
[`dialogue-extension-guide.md`](../ai-docs/docs/modules/dialogue/dialogue-extension-guide.md)，本章只讲策划要动手的部分。

### 11.1 文件在哪

| 文件 | 放什么 |
| --- | --- |
| `Tables/Data/dialogue/<编号>.json` | **一个文件一棵对话树**，文件名就是编号（现有 `1001.json`、`1002.json`，新写一段照着抄） |
| `Tables/Data/dialogue_character.json` | 角色表：一个文件放全部角色，每个角色的 `id`、`displayName`（显示名）、`defaultExpression`（默认表情）、`expressions`（表情 id → 立绘地址） |

一棵树的外层是 `id`（编号）、`entry`（从哪个节点开始）、`nodes`（节点列表）。每个节点的字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 节点名，同一棵树里不重复，`next` 靠它跳转 |
| `revision` | 修订号，填 `1`；**改已上线台词的文字时 +1** |
| `kind` | `Line` 一句台词 / `Choice` 一组选项 / `End` 结束 |
| `speaker` | 说话角色的 id（对应角色表）；空串 = 旁白 |
| `speakerName` | 临时改显示名；空串 = 用角色表的显示名 |
| `side` | 立绘站哪边：`Left` / `Right` |
| `expression` | 表情 id；空串 = 角色默认表情 |
| `clearOther` | `true` 时清掉另一侧立绘（旁白忽略） |
| `text` | 台词正文 |
| `next` | 下一个节点；`Line` 必填 |
| `outcome` | `End` 节点的出口码（如 `Accepted`），程序按它决定后续；不同结局用不同的 `End` |
| `blocking` | 填 `true` |
| `choices` | 只有 `Choice` 节点填，其余写 `[]` |

每个选项：`id`、`text`；**`next`（跳到哪个节点）和 `outcome`（直接结束并给出口码）二选一，另一个写空串**；
`icon` 选项左侧的小图标地址（如 `Dialogue/ChoiceIcon_Go`，没有写 `""`）；
`anyOf` 出现条件：外层任一组满足即可，组内 `all` 里的条件要全部满足，空数组 = 无条件；
条件不满足时 `hideWhenUnavailable` 为 `true` 就藏起来，为 `false` 就置灰并显示 `unavailableReason`。
条件事实能用哪些（`PlayerSneaking`、`StoryFlag` 等）以 `Tables/Defines/dialogue.xml` 里的 `ConditionFact` 为准，要新增找程序。

> **JSON 不允许缺字段。** 哪怕是空串、空数组、`false`，每个字段都要写出来。漏一个，生成时就报错。
> 最稳的做法是整段复制一个现成节点再改。

### 11.2 生成与挂到 NPC 上

1. 改完 JSON，跑 `scripts/gen-tables.ps1`，或 Unity 菜单 **21Days → 配置表 → 生成**（和第 4 章同一步）。
2. 场景里选中 NPC，在 Inspector 的 `Dialogue Interactable` 组件上把 **Dialogue Id** 填成你的编号。
3. 从 Boot 场景 Play → 标题点「开始」进入玩法，走到 NPC 旁按确认键或点右下角「对话」。**直接 Play 玩法场景不会有对话。**

跳转写错、选项 `next` / `outcome` 两个都写或都不写、表情不存在，都会在第一次打开对话时报红字，消息里带对话编号。

### 11.3 不走表的两处

- **只说一句闲话的 NPC**（没有对话树）：Dialogue Id 填 `0`，台词写在同一组件的 **Bubble Lines** 里，交互时头顶气泡按顺序轮流说。
  这部分**暂时没进表**，也不参与本地化，改了要保存场景。
- **对话手感**：`Assets/_Project/Data/Dialogue/DialogueConfig.asset` 里改打字速度（字/秒）、倍速档（默认 x1/x2/x4）、
  三连点补全（打字中连点几次、每两次间隔多久内算连点）、自动播放每句停留秒数。改法同第 3 章。

## 12. 配一条任务

任务和对话一样是 **JSON 文本文件**，经 Luban 生成。任务怎么接取、怎么推进、指引怎么找目标，规则都在
[任务模块说明](modules/quest.md) 第 3 节；每个字段的含义与取值在它的第 4 节，本章不重复字段表，只带你从零配出一条能玩的任务。

### 12.1 文件在哪

- `Tables/Data/quest/<编号>.json`：**一条任务一个文件，文件名就是编号**，和文件里的 `id` 保持一致。
- 编号惯例：主线用 1xxx（现有 `1001`、`1002`），支线用 2xxx（现有 `2001`、`2002`）。这只是习惯，程序不检查，但别乱，方便大家一眼认出类型。
- **最稳的做法：复制 `1001.json`，改文件名和里面的内容。** 外层六个字段是 `id`、`kind`（`Main` 主线 / `Side` 支线）、`title`、`description`、`prerequisites`、`objectives`。
- 和对话表一样，**每个字段都要写出来**，空的写 `""` 或 `[]`，漏一个生成就报错。`Main` / `Side` / `TalkTo` 这些是英文名，大小写一个都不能差。

### 12.2 写目标

`objectives` 里一个 `{ }` 就是一个目标，五个字段 `text`、`kind`、`key`、`count`、`location` 都要写。三种目标各一个最小例子：

**与某人对话**（`key` 填对话编号，写成带引号的数字，这段对话必须已经在 `Tables/Data/dialogue/` 里）：

```json
{ "text": "与长者谈谈", "kind": "TalkTo", "key": "1001", "count": 1, "location": "" }
```

**到达地点**（`key` 填地点键，要和场景里任务地点的 Location Key 一字不差，见 12.4）：

```json
{ "text": "前往营地", "kind": "ReachLocation", "key": "camp", "count": 1, "location": "" }
```

**计数**（`key` 填和程序约定好的键，`count` 填要几次）：

```json
{ "text": "打开物资箱", "kind": "Counter", "key": "crate", "count": 3, "location": "" }
```

> 计数目标**目前只能占位**：游戏里还没有任何玩法会上报计数，现有的 `2002.json`「清点营地物资」就是这样，接得到、做不完。要做能完成的计数任务，先找程序加上报来源。

几条规矩：

- **目标严格按顺序完成**，前一个没做完，后一个不会提前累计。上面 `1001.json` 就是「先和长者谈，再去营地」。
- `count` 从 `1` 起；大于 1 时任务栏显示「打开物资箱 1/3」这样的进度。填 `0` 或负数不会报错，会被悄悄当成 1，别靠它表达别的意思。
- `location` 一般写 `""`：到达地点自动指向自己的地点，与某人对话自动指向挂着那段对话的 NPC。只有想让指引箭头指去别处（比如计数目标想指向物资堆放点）才填一个地点键。
- 与某人对话目标：玩家在这个目标**成为当前目标之后**再聊才算，之前聊过的不算；对话以任何方式结束都算完成。

### 12.3 串成主线 / 挂支线

`prerequisites` 决定这条任务什么时候自动接取（没有「找 NPC 接任务」这一步）：

| 写法 | 意思 |
| --- | --- |
| `[]` | 第一次进游戏就接取（`1001`、`2001`、`2002` 都是） |
| `[1001]` | 1001 完成后接取（`1002` 就是这么接在 1001 后面的） |
| `[1001, 2001]` | 两条**都**完成才接取 |

- **主线同一时刻只开一条**。多条主线同时满足前置时，编号小的先接，其余排队等它完成。所以串主线就是一条接一条写前置：`1003` 写 `[1002]`，`1004` 写 `[1003]`……
- **支线不限条数**，同时满足前置就同时接取。支线也可以挂在主线后面，比如写 `[1001]` 表示「找到营地后才出现」。
- **不能成环**：A 的前置写 B、B 的前置又写 A，两条永远接不到，任务系统直接启动失败（见 12.6）。
- 前置里写的编号必须真的有这条任务，写了不存在的编号同样启动失败。

### 12.4 场景里放地点

「到达地点」目标要求场景里有一个挂着 **Quest Location** 组件的物体，它的 **Location Key** 和表里的 `key` 一致。现有两个都在 `Assets/Scenes/SampleScene.unity` 里：

| 场景里的物体 | Location Key | Radius |
| --- | --- | --- |
| `QuestLocation_Camp` | `camp` | 2 |
| `QuestLocation_Lookout` | `lookout` | 2 |

- 用现成的地点就直接在表里填 `camp` 或 `lookout`，场景不用动。
- 要新地点：**最省事是让程序放**；自己动手就在 Hierarchy 里选中 `QuestLocation_Camp` → `Ctrl+D` 复制 → 改名 → 拖到想要的位置 → Inspector 里改 **Location Key**（英文小写，比如 `well`）和 **Radius** → `Ctrl+S` 保存场景。
- **Radius** 是判定半径（米）：玩家走进这个圈就算到达。选中物体时场景视图里有一个黄色线框球，就是这个圈。
- 地点键**同一场景里不能重复**，重复了只认先登记的那个，Console 会出黄字 `地点键「camp」重复`；Location Key 留空的地点不参与任务，黄字 `没填地点键`。
- 地点**只在当前场景里有效**。现在只有一张可玩场景，别把目标配到还不存在的场景里。
- 场景是否要改找程序确认一下：`SampleScene.unity` 是大家共用的文件，两个人同时改会冲突，和 `.xlsx` 一样先吱一声。

### 12.5 生成与验证

1. 保存 JSON，照 [第 4 章 4.2](#42-六步流程) 的第 4、5 步：Unity 菜单 **21Days → 配置表 → 生成**，看 Console 出现「生成完成，资产已刷新」。
2. 打开 `Assets/_Project/Scenes/Boot.unity` → Play → 标题点「开始」。**直接 Play 玩法场景没有任务系统。**
3. 看画面左侧任务栏：开局接取的任务应该出现（默认追踪当前主线）；有前置的任务要先把前置做完，完成瞬间会弹「接取任务：xxx」。
4. 点任务栏打开任务面板，左边列表里应该有你的任务，点它看标题、描述和全部目标；想看支线的指引就点「追踪」。
5. 有地点的目标：目标在画面内时头顶浮任务标记，在画面外时画面边缘出现箭头和距离。走进圈里，任务栏应切到下一个目标。

### 12.6 改出问题了怎么办

**任务表只要有一处写错，整个任务系统就起不来**：进游戏后没有任务栏、没有任何任务，但游戏本身照常能玩，很容易以为是没刷新。这时 Console 里会有一条红字，开头是：

`[Game] QuestService：任务表校验失败，任务系统本次不可用（查询返回空、上报被忽略）。修表后重启。原因：`

「原因：」后面那句告诉你是哪条任务出错，对照下表：

| 「原因：」后面出现 | 说明 | 怎么办 |
| --- | --- | --- |
| `任务 1003：id 重复` | 两个文件里写了同一个 `id` | 改掉其中一个，文件名也跟着改 |
| `任务 1003：前置任务 1009 不存在` | `prerequisites` 里写了没有的编号 | 改成真实存在的任务编号 |
| `任务 1003：前置关系成环（经由任务 1002）` | 前置互相指，谁也接不到 | 理顺先后，去掉其中一条前置 |
| `任务 1003：目标列表为空` | `objectives` 写成了 `[]` | 至少写一个目标 |
| `第 0 个目标的文本为空` | 目标的 `text` 是空串 | 填上目标文字 |
| `第 0 个目标是对话，键「长者」不是角色 id 整数` | 对话目标的 `key` 没填数字（提示里写的「角色 id」其实指对话编号） | 改成对话编号，如 `"1001"` |
| `第 0 个目标引用的对话 1009 不在对话表里` | 对话编号在 `Tables/Data/dialogue/` 里找不到 | 先写这段对话，或改成已有的编号 |
| `第 0 个目标是抵达地点，地点键为空` | 到达地点目标的 `key` 是 `""` | 填地点键，如 `"camp"` |
| `任务 1003：id 必须为正数` | `id` 写了 0 或负数 | 用 1xxx / 2xxx 的正整数 |

> 注意：**「第 0 个目标」就是第一个目标**，程序从 0 开始数，第二个目标报的是「第 1 个」。

不在上表里的两种情况：

- **生成就失败了**（`[配置表] 生成失败，退出码 N`）：多半是 JSON 本身写坏了——漏字段、漏逗号、括号没配对、`kind` 写成了 `main` 这类不认识的英文名。往上翻 Luban 的原始报错，一般会带 `quest` 和文件名，照第 8 章对号入座。
- **任务出来了，但走到地点不完成**：Location Key 和表里 `key` 不一致（大小写也算），或者地点在别的场景里；看有没有 `重复` / `没填地点键` 的黄字。

改完**重新生成，再从 Boot 进一次 Play**；任务系统只在开局读一次表，不退出 Play 改了也不生效。
