## 二、关键取舍

| 取舍 | 理由 |
| --- | --- |
| IMGUI 而非 UI Toolkit | 与现有窗口一致，subagent 出错率低；代价是没有拖拽排序，用 ▲▼ 代替 |
| JSON 仍是唯一数据源 | 编辑器不引入 SO 中间层，避免「两份真相」；手改 JSON 与用编辑器可混用 |
| 校验器最后用 `QuestContent` 兜底 | 编辑期规则是「聚合 + 友好文案」，可能有漏网之鱼；运行时规则是真相，兜底保证「编辑器绿 = 运行时能起」 |
| 计数键按类型名 `t:LootConfig` 找资产读值，不编译期引用 `Game.Loot` | Loot 是另一会话未提交的模块，编译期依赖会在提交顺序不对时打断 HEAD；缺席时只是没有已知计数键，不报错 |
| 运行时保持遇错即抛 | 编辑期已经把错拦干净，运行时没必要为极小概率的漏网之鱼改成「跳过坏任务继续跑」，增加隐藏 bug 的空间 |

## 三、刻意没做的（别重新提议）

- 拖拽排序：▲▼ 已经够用，拖拽在 IMGUI 里成本不成比例。
- 可视化节点图：任务数量和分支都不复杂，「主线链 + 支线分组列表」已经能表达编排。
- 改 Luban schema：本期不加字段，任何新需求先看现有五个目标字段能不能表达。
- 运行时跳过坏任务继续跑：保持 fail-fast，靠编辑期把错拦干净，不给隐藏 bug 留空间。

## 四、验证怎么做的

四个现有 JSON 经「载入 → 保存」后 `git diff Tables/` 为空（往返逐字节相等）；故意改坏一处（前置指向自己、
对话键改非法字符）后校验菜单列出对应错误、`TryGenerate` 返回 false 且 `.bytes` 未动；全量 EditMode 609/609
（Quest 命名空间 116/116）；派 `code-reviewer` 审 `Editor/Quest/` 与 `GenerateTablesMenu.cs`，PASS，唯一 WARN
（改编号迁移文件失败时报错不明确）已修；编辑器窗口开一次截图肉眼看布局。

## 五、教训

多会话共用一个工作区时，第一笔提交混进了六个别人暂存但不属于本轮的文件——根因是 `git commit` 提交的是整个索引，
索引是共享的。往后按路径提交（`git commit -F <信息文件> -- <路径…>`），提交后 `git show --stat` 核对；已沉淀进
[`ai-docs/pitfalls.md`](../../ai-docs/pitfalls.md) 与 [`docs/commit-convention.md`](../commit-convention.md)。
