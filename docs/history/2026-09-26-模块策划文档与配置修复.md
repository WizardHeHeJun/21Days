## 一、这一天做出了什么

起因是一句话：「每个模块都没有文档说明，给策划看的也没有。」核对下来，程序三件套在 `ai-docs/docs/modules/` 一直齐全，缺的是两层：人读的模块总览，和策划 / 美术视角的逐模块说明。

- **模块总览** `docs/modules/README.md`：十个模块的成熟度、是否挂进 Boot、策划说明、三件套入口、主要可调项各一列；附口径定义与维护规则。
- **九份策划 / 美术说明** `docs/modules/<模块>.md`（Player、Monster、Disguise、Taming、IsometricExploration、CharacterPuppet、Dialogue、Quest、Narrative），统一七节骨架：一句话 → 玩家看到什么 → 规则 → 能改什么（表：想改什么 / 在哪改 / 字段 / 影响 / 备注，带现值）→ 现有内容 → 已知限制（引用 roadmap 行编号）→ 与其他模块的关系。对话与任务两份把表字段逐个解释。
- **四处入口**：仓库 README 文档列表、开发者手册第 7 章、策划手册「我要做 X」路由表、`ai-docs/docs/catalog.md`。
- **策划手册第 12 章「配一条任务」**：从复制 `1001.json` 到进 Play 验证的手把手流程，报错对照表直接对着代码里的校验文案写，包括「第 0 个目标就是第一个」。
- **写手顺带揪出的问题，当天修掉五项**：对话 `1002` 说话人由老者改为旅人并重生成配置表；`QuestConfig.asset` 补写三个只存在于代码默认值里的字段；拼接小人步频参数改为 0.53 / 0.8 / 2.8，让走路与奔跑的腿速可区分；拼接小人 PRP 里「7 张 PNG」改正为 5 张图 7 个分件；核实键盘 / 手柄当时不能推进台词并写进文档。
- **回放补步**：`CharacterPuppetShowcase` 加「以 3 向右 1 秒 → 以 5 向左 0.6 秒回原点 → 停下」三步，直接读 Animator 的 Speed 参数校验倍率约 1.6 / 2.65，回放 8 步全过、截图在画内，开发者看过点头。
- 同日早些时候还落了两件收尾：参考对标与补足路线图 `docs/roadmap.md` 进库，对话与任务两份 PRP 任务清单里「已提交」的勾回填。

## 二、关键取舍与理由

- **策划文档一模块一份放 `docs/modules/`，不塞进策划手册。** 手册已 360 行、是流程书；逐模块的规则与参数是参考书，放一起两边都难翻。固定七节骨架让三个写手并行产出仍然长得一样。
- **三件套不重写，只链接。** Disguise、Taming 的三件套只有十几行，一度想「补厚」，看了源码才知道 Disguise 整个模块 9 行——文档薄是模块小，不是文档差。
- **Sample 不写策划文档**，总览里标「样板，策划不用管」。
- **文档按工作区写还是按 HEAD 写。** 三个会话同时在改，写手读到的是别人未提交的功能（走跑切换、沉浸模式、任务通知、支线 2002），全写成了现状。没有回退重写，而是在总览末尾加一句「以实际合入为准，合入后删」兜底；教训沉淀成派单纪律。
- **步频参数选 0.53 / 2.8 而不是别的。** 原参数 0.8 / 1.6 让走路 3 与奔跑 5 都被上限截成 1.6 倍。新值保留走路约 1.6 倍的既有手感，只让奔跑升到约 2.65 倍、潜行落到下限 0.8 倍。先跑原回放确认潜行档没坏，再补走跑两步锁住差别。
- **回放补步的走向。** 第一版走 3 两秒、跑 5 两秒一路向右，检查点靠读状态全绿，截图却是空的——验证场景镜头固定。改成向右 1 秒再向左 0.6 秒回原点，后面的时停截图也保住了。
- **提交按类型拆细。** 一天 13 个提交，docs / fix / chore / test 各归各，看提交列表就能知道动了什么，也方便别的会话「按文件挑」。

## 三、刻意没做的（别重新提议）

- **不碰另外两个会话正在改的类文件。** 探索配置里两个游戏不读的字段（`moveSpeed`、`sortingScale`）本想删，因白盒会话正在同一文件加探索 HUD 字段，改为用跨会话消息移交，对方当天顺手删掉；任务配置的 `Hover Offset` 遗留字段、玩家配置的 `runSpeed` 写入资产，同理留给对方合入时处理。
- **不给 `Runtime/<模块>/` 目录加 README**，不在开发者手册里逐模块展开：入口有一个就够，多处维护必然漂移。
- **不把「并发会话写手污染」写进 `pitfalls.md`**：那份文件对方正在改，且这条主要是主窗口的派单纪律，落在跨会话记忆里。
- **不进 Play 手动试走跑手感**：编辑器与另外两个会话共用，切 Play 会打断别人；用回放补步替代，视觉由开发者看截图定。
- **支线 `2002` 的计数键没有上报来源，不处理**：白盒会话的 Loot 模块正在做物资箱，那就是它的来源。
- **第 12 章不重复任务表字段表**，链接到 `docs/modules/quest.md` 第 4 节；字段解释只维护一处。

## 四、与并行会话

这一天同一个工作区、同一个 git 索引上有三个 Claude Code 会话：一个做 roadmap 状态回填、Narrative 三件套、Sample 与 replay 补记、对白键盘操作；一个做探索白盒（Loot、探索 HUD 与 Installer、删旧触屏控件）；本会话做文档与配置修复。

- **只碰自己的文件**；改到共享文件（`catalog.md`、开发者手册、任务 PRP 清单）时按 HEAD 基线重放只入自己的行，`hash-object` + `update-index` 单独进索引。
- **共用索引里有别人的暂存项**（对方 `git rm` 的触屏控件）：每次提交前记录其路径与 blob，`reset` 退回，提交完原样放回。七次提交都这么倒腾，对方那边状态始终不变。
- **重生成配置表前先快照** `Data/Config/` 与 `Core/Config/Generated/`，生成后 `diff -rq`，只允许自己改的那张表的 `.bytes` 有差异；实际零误伤。
- **跨会话消息**用来通报改动、移交任务、接收决定：PC 优先（触屏与走跑按钮延后到移动端移植）就是经另一会话转达的，随即把五份文档里「触屏还没做」改成「延后」。
- **MCP 跑测试会与对方竞态**：`run_tests` 报「tests_running」不一定是失败，先读 `editor/state` 找 `current_job_id` 再 `get_test_job` 等；域重载会留下没启动的孤儿任务，对方用 `clear_stuck` 清过一次。

## 五、踩到的坑（已沉淀）

- 写手把对方未提交功能写成现状 → 跨会话记忆：派文档写手前查 `git status`，指定读 HEAD 或要求标注。
- 固定镜头下回放累计位移出画、检查照样绿 → [`module-verify.md`](../../.claude/rules/module-verify.md) 编写规范加一条：各步位移要收尾回原点。
- `gc_scan` 会把对方刚生成一半的三件套报成失效链接，隔一分钟再跑就没了；看到 narrative 目录的报错先别修。
- 对话文档第 6 节回填结论时写手带了类名，验收时改成白话：策划文档里代码标识符只允许资产名、表名、Inspector 字段名。
